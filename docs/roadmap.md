# Neural Learning Lab - Roadmap

## Назначение документа

Этот документ определяет объём **MVP**, проверяемые критерии его готовности и направления развития до **версии 1.0**.

Главный результат проекта - не максимальное число поддерживаемых моделей, а рабочая система, которая помогает **поставить эксперимент → обучить модель → наблюдать обучение → сохранить результаты → сравнить запуски → сформулировать вывод**.

Статусы задач отмечаются чекбоксами. Новые идеи, не обязательные для завершения MVP, следует помещать в раздел версии 1.0 или последующий backlog.

---

## 1. MVP - первая законченная версия

### 1.1. Пользовательский сценарий

Пользователь должен иметь возможность:

1. Выбрать поддерживаемый датасет и совместимую архитектуру.
2. Настроить основные гиперпараметры и запустить обучение.
3. Посмотреть ход обучения и характеристики полученной модели.
4. Открыть сохранённый запуск с его конфигурацией, метриками и артефактами.
5. Сравнить два эксперимента, увидеть различия их условий и оценить полученные результаты.

### 1.2. Функциональные требования

#### Данные и подготовка

- [ ] Поддерживается **Two Moons** - синтетическая задача бинарной классификации для MLP и визуализации границы решений.
- [ ] Поддерживается **Fashion-MNIST** - задача классификации изображений для MLP и CNN.
- [ ] Для каждого датасета задан корректный протокол `train / validation / test`; разбиение повторяемо при фиксированном seed.
- [ ] Предобработка определяется конфигурацией и не использует информацию из validation/test для подгонки преобразований.
- [ ] **Test** используется для итоговой оценки выбранной конфигурации, а не для подбора гиперпараметров.

#### Модели

- [ ] Реализована **MLP** на PyTorch с настраиваемым числом скрытых слоёв, шириной и функцией активации (**ReLU / Tanh**).
- [ ] Реализована **небольшая CNN** на PyTorch для Fashion-MNIST (в MVP архитектура фиксирована).
- [ ] Модели выдают logits корректной формы; выходные размерности согласованы с задачей и числом классов.
- [ ] Отображается количество обучаемых параметров модели.
- [ ] Несовместимые комбинации модели и датасета отклоняются с понятным сообщением.

#### Обучение

- [ ] Реализован собственный переиспользуемый **training/evaluation loop** поверх `torch`/`torch.autograd`.
- [ ] Можно выбрать оптимизатор **SGD** или **Adam**.
- [ ] Настраиваются **learning rate, batch size, число эпох**.
- [ ] Поддерживаются **Dropout** и **weight decay** (для применимых моделей и конфигураций).
- [ ] Обучение работает на **CPU**, а при наличии CUDA - на **GPU**; отсутствие GPU не ломает приложение.
- [ ] Для каждой эпохи рассчитываются **train/validation loss и accuracy**.
- [ ] Время обучения измеряется и сохраняется; ошибка обучения не приводит к потере уже записанной конфигурации и доступных результатов.

#### Диагностика и визуализация

- [ ] Строятся кривые **train/validation loss** и **accuracy** по эпохам.
- [ ] Собираются и визуализируются **нормы градиентов параметров по слоям** (хотя бы раз в эпоху).
- [ ] Для Two Moons визуализируется **decision boundary** обученной MLP.
- [ ] Для Fashion-MNIST можно посмотреть **примеры изображений и предсказания** модели.
- [ ] Показываются итоговые метрики, число параметров и продолжительность запуска.

#### Эксперименты и сравнение

- [ ] Каждый запуск получает **уникальный идентификатор** и сохраняет полную конфигурацию: датасет, модель, гиперпараметры, seed и способ разделения данных.
- [ ] Сохраняются **метрики по эпохам, диагностические показатели и checkpoint весов** (достаточный для загрузки и инференса).
- [ ] Сохраняется минимальная информация об окружении: версии Python/PyTorch, тип устройства, версия приложения.
- [ ] В интерфейсе доступна **история запусков** и просмотр результатов завершённого запуска после перезапуска приложения.
- [ ] Можно выбрать **два запуска** и увидеть общие графики метрик, итоговую сравнительную таблицу и различия конфигураций.
- [ ] При сравнении видны значимые различия условий (например, датасета или разбиения), чтобы не трактовать несопоставимые результаты как честный эксперимент.

#### Интерфейс

- [ ] Есть простой **интерактивный интерфейс** (план: Streamlit): настройка → запуск → результаты → история → сравнение.
- [ ] Ошибочные значения параметров проверяются до старта обучения; сообщения об ошибках понятны пользователю.
- [ ] Ядро обучения и экспериментов **не зависит от UI**: его можно запускать отдельно, например из Python или CLI.

### 1.3. Инженерное качество - обязательная часть MVP

- [ ] Проект организован как Python-пакет с разделением ответственности: модели, данные, обучение, эксперименты, диагностика, визуализация, UI.
- [ ] Зависимости и запуск воспроизводимы через **`uv`**; есть `pyproject.toml` и инструкция установки.
- [ ] Написаны **unit tests** для конфигураций, создания моделей, форм выходных тензоров и вычисления метрик.
- [ ] Есть **integration/smoke test** короткого обучения на CPU: веса обновляются, loss остаётся конечным, pipeline завершается успешно.
- [ ] Есть проверка сохранения и загрузки checkpoint: восстановленная модель даёт те же предсказания в режиме `eval()` при одинаковом входе (с допустимой численной погрешностью).
- [ ] Есть проверка корректного сравнения и восстановления сохранённых запусков.
- [ ] Настроен **CI** для быстрых CPU-тестов и базовых статических проверок (например, Ruff).
- [ ] Есть `README.md` с описанием, установкой, запуском и примером эксперимента.
- [ ] Есть краткие документы с требованиями, архитектурой и ключевыми инженерными решениями.

### 1.4. Definition of Done - как принимаем MVP

MVP считается готовым, **когда выполнены все условия ниже**:

- [ ] **Сценарий A - MLP / Two Moons:** пользователь запускает две конфигурации MLP, видит loss/accuracy, gradient norms и decision boundaries, затем сравнивает результаты.
- [ ] **Сценарий B - MLP vs CNN / Fashion-MNIST:** обе модели обучаются на согласованных train/validation split; сохраняются метрики и checkpoints; сравнение доступно через UI.
- [ ] **Сценарий C - сохранение:** после перезапуска приложения можно открыть завершённый запуск, восстановить его конфигурацию, графики и веса модели для предсказания.
- [ ] **Сценарий D - повторение:** запуск с сохранённой конфигурацией и seed в задокументированном окружении даёт сопоставимые результаты; известные ограничения детерминизма описаны.
- [ ] **Сценарий E - качество:** тесты и CI проходят, а новый разработчик может запустить проект по README.
- [ ] **Исследовательский результат:** проведено и описано **хотя бы одно контролируемое исследование** (гипотеза, условия, результаты, ограничения, вывод). Например, влияние глубины MLP или learning rate на обучение. В выводах не используются test-данные для выбора гиперпараметров.

**Важно:** достижение произвольного порога accuracy не является критерием готовности. Проверяется корректность работы лаборатории и содержательность эксперимента, а не соревнование за лучшую метрику.

### 1.5. Рекомендуемый порядок реализации

Это последовательность **вертикальных срезов**: на каждом этапе появляется работоспособная часть пользовательского сценария.

1. **Первое обучение:** Two Moons → MLP → PyTorch training loop → график loss.
2. **Эксперимент как объект:** конфигурация → уникальный run ID → сохранение метрик и checkpoint.
3. **Сравнение:** история запусков → наложение графиков → различия конфигураций.
4. **Расширение моделей:** Fashion-MNIST → MLP → CNN на общем training engine.
5. **Исследовательская диагностика:** gradient norms, визуализация предсказаний, decision boundary, показатели модели.
6. **Финализация:** обработка ошибок, тесты/CI, документация, одно исследование и демонстрация.

### 1.6. Что сознательно НЕ входит в MVP

- Произвольный визуальный конструктор слоёв и архитектур.
- Поддержка пользовательских датасетов, произвольных форматов и любых задач ML.
- Автоматические серии запусков (sweeps) и массовые multi-seed исследования.
- Transformers, residual networks, крупные предобученные модели.
- Полноценный мониторинг активаций, профилирование GPU и распределённое обучение.
- AutoML, автоматическая интерпретация выводов, сложный frontend, микросервисы и production deployment.

## 2. Версия 1.0 - полноценная исследовательская лаборатория

**Цель:** расширить MVP до системы, на которой удобно проводить серии контролируемых DL-экспериментов с разными архитектурами, собственными данными и более глубокой диагностикой. Ниже - **целевой backlog 1.0**; порядок и детализация будут уточняться по итогам MVP.

### 2.1. Архитектуры моделей

- [ ] **MLP:** более гибкие конфигурации ширины по слоям, дополнительные активации (например, GELU), выбор инициализации (Xavier/He), слои нормализации.
- [ ] **CNN:** настраиваемые число блоков/каналов, kernel size, pooling и размер классификационной головы.
- [ ] **Residual connections / blocks:** поддержка остаточных соединений в подходящих MLP/CNN-архитектурах и сравнение влияния на обучение.
- [ ] **Небольшой Transformer:** например, компактный **Vision Transformer (ViT)** для классификации изображений. Реализовать patch embeddings, self-attention, FFN/MLP, normalization и residual connections на PyTorch; обеспечить совместимость с единым training/experiment pipeline.
- [ ] Для каждой архитектуры доступны сведения о структуре, числе параметров и совместимых датасетах.

**Почему ViT:** он позволяет добавить настоящий Transformer без обязательного расширения MVP до полноценного NLP-пайплайна; для начала можно обучать маленькую модель на CIFAR-10. 

### 2.2. Датасеты и данные

- [ ] Встроен **CIFAR-10** для экспериментов с CNN, residual networks и небольшим ViT.
- [ ] Поддерживается **загрузка пользовательских датасетов**, с явно ограниченными форматами:
  - [ ] **CSV** для табличной классификации (пользователь задаёт целевую колонку и поддерживаемые числовые признаки; категориальные признаки - отдельное расширение).
  - [ ] **Папки изображений по классам** (`ImageFolder`-подобная структура) для CNN и ViT.
- [ ] Проверяются формат, классы, размеры входов, пропуски и совместимость датасета с моделью.
- [ ] Реализованы воспроизводимые train/validation/test split и конфигурируемая предобработка без утечки данных.
- [ ] Поддерживаются **data augmentation** и экспериментальное изменение характеристик данных (например, размер обучающей выборки или уровень шума).

*Граница 1.0:* «пользовательские датасеты» не означает поддержку произвольных CSV, текстов, аудио и любых ML-задач без ограничений.

### 2.3. Оптимизация и регуляризация

- [ ] Добавлены **SGD with Momentum** и **AdamW** (помимо SGD и Adam).
- [ ] Реализованы **learning-rate schedulers** (например, StepLR и CosineAnnealingLR).
- [ ] Поддерживается настраиваемая **инициализация весов**, где это применимо.
- [ ] Добавлены **Early Stopping** и конфигурации нормализации.
- [ ] Расширены эксперименты с **Dropout, weight decay и data augmentation**.

### 2.4. Продвинутая диагностика

- [ ] Анализируются **распределения активаций** и доля неактивных ReLU-нейронов (где применимо).
- [ ] Отслеживаются **распределения и нормы градиентов** во времени, включая выбранные промежуточные активации.
- [ ] Добавлены **отношения величины обновления к норме параметров** (`update-to-weight ratio`) и другая диагностика стабильности.
- [ ] Диагностика включается выборочно и с настраиваемой частотой, чтобы не создавать избыточный overhead.
- [ ] В UI доступны сравнительные визуализации этих показателей.

### 2.5. Управление сериями экспериментов

- [ ] **Parameter sweeps:** автоматически запускается заданная сетка значений одного или нескольких параметров.
- [ ] **Multi-seed experiments:** одна конфигурация может запускаться с несколькими seeds.
- [ ] Результаты серии агрегируются как **mean/std** (и, при необходимости, доверительные интервалы), а отдельные запуски остаются доступны.
- [ ] Поддерживаются последовательное выполнение, отслеживание статусов, повторный запуск неуспешных экспериментов и управление историей.
- [ ] Отчёты явно различают контролируемые сравнения и сравнения с несколькими изменёнными условиями.

### 2.6. Аналитика и отчёты

- [ ] Добавлены **confusion matrix, per-class metrics и анализ ошибочных предсказаний**.
- [ ] Можно сравнивать серии экспериментов, а не только два запуска.
- [ ] Есть **экспорт графиков, таблиц и исследовательского отчёта** (например, Markdown/CSV/PNG).
- [ ] Подготовлены воспроизводимые исследовательские сценарии:
  - **Optimization Dynamics:** SGD/Momentum/Adam/AdamW, learning rate, batch size, schedulers.
  - **Architecture & Gradient Flow:** глубина, инициализация, активации, residual connections.
  - **Generalization & Regularization:** dropout, weight decay, early stopping, augmentation, размер train set.

### 2.7. Дополнительные критерии готовности версии 1.0

- [ ] Все сценарии MVP продолжают работать; регрессионные тесты проходят.
- [ ] **Transformer** обучается через тот же экспериментальный pipeline, что и MLP/CNN, а его результаты доступны в истории и сравнении.
- [ ] Пользователь может загрузить **один поддерживаемый CSV** и **один image-folder dataset**, обучить совместимые модели и корректно получить метрики.
- [ ] Можно запустить **один parameter sweep с несколькими seeds** и получить сравнительный отчёт с агрегированными метриками.
- [ ] Представлены не менее **трёх воспроизводимых исследовательских кейсов**, по одному на оптимизацию, архитектуру и обобщение.
- [ ] Обновлены тесты, документация архитектуры и инструкции воспроизведения экспериментов.

## 3. После версии 1.0 - возможные направления

Эти идеи **не являются обязательствами по MVP или версии 1.0**:

- Transformer для NLP (например, классификация текста или небольшой decoder-only language model).
- Mixed precision, gradient accumulation/checkpointing, профилирование GPU и оптимизация производительности.
- Более сложные архитектуры, transfer learning и поддержка новых типов задач.
- Собственные исследовательские плагины, расширенные аналитические панели и экспорт дополнительных форматов отчётов.

## 4. Приоритеты разработки

1. **Корректное обучение и оценка** важнее числа моделей.
2. **Воспроизводимость и сравнение** важнее количества настроек в интерфейсе.
3. **Исследовательские выводы** важнее визуального оформления.
4. **Тестируемая модульная архитектура** важнее преждевременной универсальности.
5. Любая новая функция должна либо помогать исследовать поведение нейросетей, либо делать такие исследования надёжнее и удобнее.
